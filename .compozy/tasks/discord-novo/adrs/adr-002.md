# ADR-002: Minimal MVP Scope — Only GITHUB and AUTOMAÇÕES Categories

## Status

Accepted

## Date

2026-05-27

## Context

The Future Station Discord server currently has a single generic "Canais de Texto" category holding all nine text channels, plus a "Canais de Voz" category for voice. The original plan in `prompt-inicial.txt` proposed a six-category reorganization (INFORMAÇÕES, CONTEÚDOS E IDEIAS, CLIENTES E PROJETOS, GITHUB, AUTOMAÇÕES, DESENVOLVIMENTO, VOZ).

During brainstorming, the user explicitly chose the minimal MVP option: create only the two new categories required to deliver the automation goal — `🔗 GITHUB` and `🤖 AUTOMAÇÕES` — and leave every existing channel untouched.

Forces at play:

- The server is small (22 members) and the team prefers low-disruption changes.
- Existing channels already serve a working flow; renaming or moving them risks confusion.
- The primary business goal is the GitHub → Discord automation, not a server-wide reorganization.
- A larger reorganization can always happen in a later phase if the team chooses.

## Decision

The MVP creates **only two new Discord categories** and the channels required to host the automation:

- `🔗 GITHUB`: `#github-teste`, `#github-commits`, `#github-pull-requests`, `#github-releases`, `#github-actions`
- `🤖 AUTOMAÇÕES`: `#n8n-logs`, `#deploys`, `#erros-producao`

All existing channels (`#geral`, `#prompts`, `#deixe-uma-música-aqui`, `#isights-vídeos`, `#n8n-videos-tutoriais`, `#para-sites`, `#banco-de-dados`, `#links`, `#chat-clientes`) remain in their current category, with their current names. No moves, no renames, no deletions.

The typo in `#isights-vídeos` is documented as an open question but not corrected in this phase.

## Alternatives Considered

### Alternative 1: Medium reorganization

- **Description**: Add GITHUB and AUTOMAÇÕES, and also move existing channels into thematic categories — `📝 CONTEÚDOS E IDEIAS` (prompts, vídeos, música, sites, banco-de-dados) and `💼 CLIENTES E PROJETOS` (chat-clientes).
- **Pros**: Cleaner long-term structure; better separation between team and client zones; easier to apply role-based visibility.
- **Cons**: Moves five existing channels, requires re-announcing locations to the team, risks short-term confusion during transition.
- **Why rejected**: User explicitly preferred the minimal option to keep the rollout low-friction.

### Alternative 2: Full reorganization (original plan)

- **Description**: Create all six categories proposed in `prompt-inicial.txt`, including a `💻 DESENVOLVIMENTO` category with per-stack channels (`#frontend`, `#backend`, `#flutter`).
- **Pros**: Matches the original aspirational design; covers every future need in one pass.
- **Cons**: ~20 new or moved channels for a 22-member server; many channels would start empty; per-stack dev channels are likely premature given current team size and lack of existing traffic patterns.
- **Why rejected**: Violates YAGNI for current team scale. The original plan explicitly warned "não crie canais demais sem justificar".

## Consequences

### Positive

- Smallest possible blast radius — only additive changes, no existing channels are touched.
- Team can adopt the new structure incrementally without disrupting current habits.
- Easier to roll back if something is wrong: delete two categories, done.
- Permission model stays simple: only the two new categories need client-hidden visibility.

### Negative

- The server retains its current generic-category layout for non-automation channels.
- If a broader reorganization is needed later, it becomes a second, separate change effort.
- Typo `#isights-vídeos` remains in place until a future cleanup pass.

### Risks

- **Risk**: Team later wants `💻 DESENVOLVIMENTO` channels but the structure no longer signals it as a planned area.
  - **Mitigation**: PRD documents Phase 4 / future evolution to add Dev channels if/when traffic justifies them.
- **Risk**: Existing channels remain visible to clients even though some (`#prompts`, `#banco-de-dados`) might be team-only.
  - **Mitigation**: Out of scope for this PRD; flagged in Open Questions for a future permissions audit.

## Implementation Notes

- New channel creation order: categories first, then channels inside each, to preserve correct visual ordering.
- Channel naming follows lowercase-with-hyphens convention already used (`#chat-clientes`, `#banco-de-dados`).
- Both new categories should be hidden from any client-facing role by default.
